# Реалізація класу Library та покриття Unit-тестами (JUnit 5) — Рефакторинг

Цей проєкт є виконанням практичного завдання з розробки об'єктно-орієнтованої логіки для керування бібліотекою книг (`Library` та `Book`) із повним покриттям коду модульными тестами.

Код тестів було повністю рефакторизовано та оптимізовано відповідно до сучасних стандартів розробки та найкращих практик JUnit 5.

## 🚀 Стек технологій
* **Java** (версія 25)
* **JUnit Jupiter (JUnit 5)** — бібліотека для тестування
* **Maven** — система автоматизації збирання проєктів
* **IntelliJ IDEA** — середовище розробки

---

## 🛠️ Опис покращень та архітектури тестування

В ході рефакторингу тестового класу `LibraryTest` було впроваджено наступні архітектурні покращення:

1. **Параметризовані тести (`@ParameterizedTest`)**:
    * Замість дублювання методів для кожної некоректної перевірки, логіку обробки `null` та пустих значень було об'єднано за допомогою аннотацій `@ParameterizedTest` та `@NullAndEmptySource`.
    * Додатково використано `@ValueSource` для перевірки граничних випадків із різними типами пробілів, табуляцій (`\t`) та переносів рядків (`\n`).

2. **Строга валідація виключень (Exception Messages)**:
    * Тепер тести не просто очікують генерацію `IllegalArgumentException`, а й детально перевіряють текст повідомлення помилки (`exception.getMessage()`). Це гарантує, що спрацював саме наш захисний блок валідації.

3. **Оптимізація пам'яті та ізоляція (Lazy Initialization)**:
    * З методу `@BeforeEach` було видалено дефолтну ініціалізацію тестової книги, яка використовувалася не в усіх сценаріях. Натомість реалізовано приватний метод фабрики `createValidBook()`, що створює об'єкт книги виключно тоді, коли це необхідно конкретному тесту.

4. **Чистий іменувальний стиль (Clean Naming)**:
    * Відповідно до стандартів JUnit 5, застарілий префікс `test` було видалено з назв усіх методів. Самі назви стали більш лаконічними та чітко описують очікувану поведінку (наприклад, `addBookSuccess`, `removeBookReturnsFalseWhenBookNotFound`).
